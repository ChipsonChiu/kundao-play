# R4 素材裁切修正版｜2026-11-07

本包是增量修正包，包含 **22 張獨立修復圖，對應 23 個素材 ID**。標準 PNG 沿用 R4 原檔名、尺寸與 anchor；瘴氣另有共用別名 `trial_zhongkui_sha`，已同步輸出。

## 查明的原因

部分沿用的舊素材從整張素材表拆出時，取框切入了主體，或帶入鄰格圖案。後續又在已缺損圖片外加上約 3 px 透明留白，導致只檢查「PNG 邊框有沒有透明」會漏掉問題。缺損已存在於母圖，因此遊戲完整畫出 PNG 時，也會顯示被截斷的輪廓。

本次另發現 9 種道具留有白色／淡粉色不規則去背殘片，一併清理。已找回的原始素材表為 `C621BC33-DB4C-4A27-87B6-48C9B4AD94F4.jpeg`；前 13 種修復均以完整原圖作參考。9 種背景清理則依現有母圖處理，未宣稱找回它們的原始生成素材表。

## 使用方式

### 遊戲直接讀取外部 PNG

將本包 `assets/` 中同名的 23 張 PNG 替換到遊戲使用的素材資料夾。這些檔案的畫布尺寸與 R4 完全一致。

若專案另外使用 `content_bounds` 取源圖範圍，請將 `metadata/catalog.patch.json` 的欄位按 ID 合併到現有清單。該檔只有本次修正項目，**不要拿它覆蓋整份完整 manifest**。若程式硬編碼了舊裁切矩形，須改為畫完整 PNG，或使用新清單的 `content_bounds`。

### 遊戲把圖片內嵌在 HTML

若載入器使用 `window.ASSETS_INLINE.assets`，單純替換外部 PNG 不會改掉 HTML 裡已內嵌的圖。可在解壓縮目錄執行：

```bash
python apply_inline_assets.py "目前遊戲.html"
```

工具只更新既有的同名素材資料，另存 `目前遊戲_crop_fixed.html` 及資產更新報告，不覆寫輸入 HTML。未使用到的素材 ID 會列在報告中，不會擅自加入遊戲。此工具只需 Python 標準函式庫，不需安裝額外套件。

只想先看可替換項目時：

```bash
python apply_inline_assets.py "目前遊戲.html" --dry-run
```

此工具支援 JSON 格式的 `window.ASSETS_INLINE.assets`；其他內嵌格式會停止並回報，不會猜測或改寫程式。

## 資料夾

- `assets/`：23 張可供遊戲替換的標準 PNG。
- `masters/`：22 張修復後原生大圖，保留 image_gen 生成的原始 bytes。
- `previews/`：修正版總覽、裁切修正前後、去背修正前後。
- `metadata/patch_manifest.json`：尺寸、anchor、來源與新 SHA256、共用別名及完整修正說明。
- `metadata/catalog.patch.json`：可按 ID 合併的素材資料。
- `metadata/generation-prompts.json`：本次修圖提示詞與參考資訊。
- `docs/`：查核紀錄與已確認／未確認範圍。

## 驗證與界線

已核對 R4 的 835 筆尺寸／manifest 對應，掃描 766 份唯一母圖 alpha，並對 87 張小尺寸舊母圖進行目視檢查；其中 59 張有完整原始素材表可供比對。27 張生成素材表拆圖未找回原始表，只完成現有母圖檢視。問號圖示的左側直線可能是字形端面，未有足夠證據判定裁切，因此未改動。

修復後 23 張標準 PNG 均已驗證尺寸、SHA256、透明邊界及小尺寸可讀性。生成原圖保留原始像素；標準輸出僅作幾何裁切、等比縮放與透明留白。可見輪廓均已檢視，不只用外框透明判定。

可取得的遊戲 HTML 是 v0.70 舊檔，其 `drawSpr` 畫完整來源圖片，沒有來源裁切矩形。它不足以代表截圖中的現行版本。本次使用該舊檔驗證內嵌更新流程：成功替換 4 個存在的同名 ID，其餘 ID 明確列為未使用，資產 JSON 之外的程式文字完全不變。**本包未交付舊版遊戲，也未宣稱已更新目前線上／Claude 裡正在執行的遊戲。**

若要直接修改現行遊戲的載入或裁切程式，需提供目前正在使用的 HTML 或專案 ZIP。
